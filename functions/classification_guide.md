# Classification Guide

대본 파일/시트가 주어졌을 때, 아래 각 타입의 특징과 비교해서 가장 가까운 타입으로 분류한다.
어느 타입에도 속하지 않거나 분류에 자신이 없는 경우, 합본에 포함시키지 않고 Log에 파일명/시트명과 사유를 기록한다.

열 이름이 없거나 불명확한 경우, functions/column_inference.md를 참조해서 패턴 기반으로 열 성격을 추론한다.

---

## 헤더 행 탐색 규칙

1행이 헤더가 아닌 경우가 많다. 다음 순서로 헤더 행을 탐색한다:

1. 1~8행을 순서대로 확인
2. 아래 대본 관련 키워드가 가장 많이 포함된 행을 헤더로 판단:
   `配音对象` / `对话文本` / `语音命名` / `流程节点` / `ID` / `功能` / `终选语音` / `台詞番号` / `时间戳` / `KR Text` / `角色` / `台词` / `韩文` / `화자` / `캐릭터` / `TimeCode`
3. 키워드가 없는 경우 non-empty 셀이 2개 이상인 첫 번째 행

헤더 위 행들(프로젝트 개요, PART 설명, 섹션 제목 등)은 모두 무시한다.

---

## 분류 우선순위

타입 분류는 아래 순서로 판단한다. 앞 조건에 해당하면 뒤는 검토하지 않는다:

1. 시트명이 `설정` → **Type_명방캐릭터**
2. 타임코드 컬럼 (`时间戳`, `TimeCode`) → **Type_무한대**
3. `流程节点` 컬럼 → **Type_전투**
4. `台詞番号`/`ボイス名` 또는 (`ID` + `功能`/`终选语音`) → **Type_캐릭터음성**
5. 캐릭터명 열이 병합셀 + 대사가 짧음 (1~3어절) → **Type_짧은음성**
6. `时长`/`预期秒数` (duration) 또는 `화자` 컬럼 → **Type_PV**
7. `角色` + `KR`/`대사` 구조이되 파일명 컬럼 없음 → **Type_PV**
8. 캐릭터명+대사 컬럼 구조 → **Type_메인**
9. 위 어디에도 해당 없음 → **UNKNOWN → Log 기록 후 스킵**

---

## 스킵 대상 (분류 전 먼저 확인)

다음에 해당하는 시트는 타입 분류 없이 즉시 스킵한다:

- 숨김 처리된 시트
- 한국어 대사가 한 줄도 없는 시트
- 대본이 아닌 관리용 시트 (美术需求, 音效需求, ID索引用 등 리소스/기술 관리 목적)
- 일본어/중국어 전용 시트 (日文, 家园线 日文 등 KR 시트가 별도로 존재하는 경우의 타 언어 시트)

## 타입 목록

### Type_메인

스토리 대본. 여러 캐릭터가 등장하며 장면 단위로 대사가 이어지는 구조.

**특징:**
- 캐릭터명 컬럼과 대사 컬럼이 별도로 존재
- 캐릭터명이 CN/KR 쌍으로 구성되는 경우가 많음
- 장면(씬) 단위 구분 컬럼 존재 (장소명, 씬 ID 등)
- 행 하나 = 대사 라인 하나
- KR 컬럼이 여러 개일 수 있음 (대사KR, 캐릭터명KR, 감정KR 등 혼재)
- 헤더 행 위치가 1행이 아닐 수 있음
- 파트/챕터 구분용 제목 행이 대사 행 사이에 끼어 있을 수 있음
- 파일명 열이 여러 개일 수 있음

**대표 사례:** 리버스1999 메인스토리, 리버스1999 캐릭터스토리, 프로젝트AP 챕터 대본, Regolith

---

### Type_PV

영상에 통으로 믹싱되는 PV/스킬PV 대본. 개별 음성 파일로 납품되지 않는다.

**특징:**
- 파일명 열 없음 (영상 통합 믹싱이므로 개별 파일명 불필요)
- 화자(캐릭터명) + 대사 + 옵티컬 구조
- duration 컬럼이 있는 경우도 있고 없는 경우도 있음 (`时长`, `预期秒数` 등)
- 헤더가 1행이 아닌 경우 있음 (빈 행 이후 헤더 등)
- 캐릭터명이 한국어로만 표기되는 경우도 있음

**대표 사례:** 리버스1999 캐릭터PV, 리버스1999 스킬PV, 아크나이츠 캐릭터PV

---

### Type_전투

전투/보스 대화 대본. 파트마다 제목 행이 끼어 있는 구조.

**특징:**
- `流程节点` 컬럼 존재 (전투 단계/트리거 정보)
- 파트 구분 제목 행이 대사 행 사이에 반복적으로 등장
- 헤더 행 위치가 1행이 아닌 경우가 많음 (빈 행 + 제목 행 이후)
- 캐릭터명 컬럼 존재
- 보스 전투와 일반 전투가 별도 시트로 나뉘어 있더라도 합본에서는 1탭으로 합산

**대표 사례:** 리버스1999 보스대화, 리버스1999 일반전투

---

### Type_캐릭터음성

특정 캐릭터 전용 음성 대본. 파일 또는 시트 자체가 한 캐릭터에 종속된다.

**특징:**
- 캐릭터명 컬럼 없음 — 파일명 또는 시트명이 곧 캐릭터
- ID 컬럼 존재 (음성 ID)
- 功能/기능 컬럼 존재 (게임 내 어느 상황에 재생되는 음성인지)
- Alt 컬럼이 있는 경우도 없는 경우도 있음
- 감정 메모가 별도 컬럼이거나 대사 옆 열에 붙어 있는 경우 모두 있음
- 아크나이츠의 경우 헤더가 일본어 (`台詞番号`, `ボイス名`)

**대표 사례:** 리버스1999 角色语音, 리버스1999 스킨음성, 아크나이츠 캐릭터 대사 시트

---

### Type_짧은음성

캐릭터명이 병합셀로 묶여 여러 행을 아우르는 구조의 짧은 대사 대본.

**특징:**
- 캐릭터명이 왼쪽 열에 병합셀로 N행 묶음 처리
- 행 하나의 대사가 매우 짧음 (1~3어절)
- 병합셀 아래에 빈 KR 행이 있을 수 있음
- 음성 파일 명명 컬럼 존재 (`语音命名` 등)
- 처리 시 병합셀 캐릭터명을 각 행에 펼쳐야 함

**대표 사례:** 리버스1999 캐릭터스토리 내 짧은 음성 시트

---

### Type_무한대

ADR/Wild 구분이 핵심인 대본. 타임코드 기반 ADR 작업과 자유 녹음(Wild) 라인이 혼재한다.

**특징:**
- 타임코드 컬럼 존재 (`时间戳`, 형식: `00:00:05.700 --> 00:00:08.140`)
- 녹음 여부 컬럼 존재 (`是否收录`, Yes/No)
- ADR/Wild 구분 컬럼 존재 (`是否有时间限制`)
- 시트 하나 = 에피소드/퀘스트 하나인 경우가 많음
- 캐릭터명 CN/KR 쌍 + 대사 CN/KR 구조
- 파일명 컬럼 존재

**대표 사례:** 레벨인피니티 L50 KR 녹음 요건서

> **주의:** 이 타입은 별도 합본 샘플 검토 후 처리 매뉴얼(Type_무한대.md)을 완성할 예정.

---

### Type_명방캐릭터

아크나이츠(명일방주) 캐릭터 파일의 설정 시트. 대본이 아닌 캐릭터 프로필 정보.

**특징:**
- 대사 없음
- 캐릭터 번호, 이름, 영문명, 레어도, 소속/출신/종족, 말투/성격 등 프로필 정보로 구성
- 구조가 일반 대본 시트와 완전히 다름 (헤더 없음, 키-값 형태)
- 합본에 포함하되 원본 형태 그대로 시트로 첨부
- 시트명이 `설정`인 경우 해당

**대표 사례:** 아크나이츠 `char_XXXX_캐릭터명.xlsx`의 `설정` 시트

---

## 분류 불가 처리

어느 타입에도 속하지 않거나 판단이 어려운 경우:
- 합본에 포함하지 않음
- Log 시트에 다음 형식으로 기록:

```
파일명 | 시트명 | 사유
예: char_9999_테스트.xlsx | Sheet3 | 헤더 구조 불명확, 한국어 대사 확인 불가, 어느 타입에도 해당하지 않음
```
