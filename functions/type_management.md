# Type Management

타입 추가, 수정, 통폐합에 관한 절차를 정의한다.

---

## 타입 추가가 필요한 경우

기존 타입 중 어느 것과도 구조적으로 달라서 **classification_guide.md의 분류 우선순위 9단계로 분류가 안 되는 경우**에만 새 타입을 추가한다.

다음은 타입 추가 사유가 **아니다**:
- 열 이름이 다른 경우 (column_inference.md로 추론 가능)
- 헤더 위치가 다른 경우 (헤더 탐색 규칙으로 처리 가능)
- 프로젝트마다 컬럼 수가 다른 경우

다음은 타입 추가 사유가 **맞다**:
- 기존 9단계 분류 기준 어디에도 해당하지 않는 구조
- 기존 타입의 처리 방식(Type_XXX.md)을 적용했을 때 데이터 추출이 근본적으로 불가능한 경우

---

## 타입 추가 시 작업 목록

1. `functions/classification_guide.md` 업데이트
   - 타입 목록에 새 타입 항목 추가 (특징 서술)
   - **분류 우선순위 9단계에 새 타입을 적절한 위치에 삽입**
   - 기존 타입과 혼동될 수 있는 경계 케이스가 있으면 명시

2. `types/Type_XXX.md` 신규 작성
   - 열 인식 및 매핑
   - 특수 처리 규칙
   - 추출 결과물
   - 예외 케이스

3. `PROJECT.md` 파일 구조 목록 업데이트

---

## 타입 수정 시 작업 목록

1. 해당 `types/Type_XXX.md` 수정
2. 분류 기준이 바뀌는 경우 `functions/classification_guide.md`도 함께 수정
3. 분류 우선순위가 바뀌는 경우 우선순위 9단계 재검토

---

## 타입 통폐합 기준

두 타입의 처리 방식이 실질적으로 동일하고, 차이점이 AI 추론으로 충분히 흡수 가능한 경우 통폐합을 고려한다.

통폐합 시:
1. 남기는 타입의 `Type_XXX.md`에 흡수된 타입의 특징/예외 케이스 추가
2. 없어지는 타입 항목을 `classification_guide.md`에서 제거
3. `PROJECT.md` 업데이트

---

## 분류 우선순위 참고 (classification_guide.md 기준)

새 타입 삽입 위치 결정 시 참조:

1. 시트명 기반 판단 (`설정` → Type_명방캐릭터)
2. 타임코드 컬럼 → Type_무한대
3. `流程节点` → Type_전투
4. ID + 功能/终选语音/台詞番号 → Type_캐릭터음성
5. 병합셀 + 짧은 대사 → Type_짧은음성
6. duration/화자 컬럼 → Type_PV
7. 角色 + KR/대사 (파일명 없음) → Type_PV
8. 캐릭터명 + 대사 구조 → Type_메인
9. UNKNOWN → Log 후 스킵

새 타입은 가장 먼저 판단되어야 하는 특징을 가진 위치에 삽입한다.
